# source-command-opsx-review

Use this skill when the user asks to run the migrated source command `opsx-review`.

## Command Template

对 OpenSpec 变更涉及的代码进行审查，输出 ✅/⚠️/❌ 分级问题报告。

**Input**: `/opsx:review [变更名]`。变更名可选；若省略则自动选中唯一活跃变更，或通过 AskUserQuestion 让用户选择。

---

## Steps

### 1. 选择目标变更

如果命令参数中提供了变更名，直接使用。否则：

```bash
openspec list --json
```

- 若只有一个活跃变更 → 自动选中并告知用户
- 若有多个活跃变更 → 使用 **AskUserQuestion tool** 让用户选择
- 若无任何活跃变更 → 提示"当前没有活跃变更"并退出

告知用户："正在审查变更：`<name>`"

---

### 2. 获取变更文件列表

执行以下命令，获取本次变更相对于 main 分支的所有改动文件：

```bash
git diff main...HEAD --name-only
```

- 若输出为空 → 提示"当前变更尚无代码改动，无需审查"并退出
- 将文件列表保存备用

---

### 3. 读取任务意图（上下文）

读取变更目录下的 `tasks.md`：

```
openspec/changes/<name>/tasks.md
```

- 若文件存在 → 提取所有任务描述（`[ ]` 和 `[x]`），作为审查时理解"代码意图"的上下文
- 若文件不存在 → 跳过，仅基于代码本身进行审查

---

### 4. 读取并审查变更文件

逐一读取步骤 2 中获取的每个文件，结合步骤 3 的任务意图，对代码进行审查。

**审查关注点**（只检查代码是否有问题，不做安全或性能分析）：
- 实现是否与任务描述的意图一致
- 有无明显 bug、空指针风险、未处理的异常路径
- 边界条件是否被覆盖
- 命名是否符合项目已有规范（对比其他文件的命名风格）
- 逻辑是否清晰，有无冗余或矛盾的代码

---

### 5. 输出分级报告

按文件逐一输出审查结果，使用以下格式：

```
## Review: <change-name>

✅ src/FooService.java — 看起来没问题

⚠️ src/BarController.java:42 — cancelJob() 没有处理 jobId 为 null 的情况，建议加前置校验

❌ src/BazDeployer.java:87 — deploy() 方法名与项目其他 deployer 命名规范不一致（项目惯例为 doDeploy），建议统一

---

共 2 个问题需要关注。（⚠️ 1 个 / ❌ 1 个）
```

**分级说明：**
- `✅`：该文件未发现问题
- `⚠️`：需要关注，可能影响健壮性或可维护性，但不一定必须修改
- `❌`：建议修改，存在 bug、逻辑错误或明显的规范违反

**末尾汇总：**
- 有问题：`共 N 个问题需要关注。（⚠️ X 个 / ❌ Y 个）`
- 无问题：`代码看起来没问题 🎉`

---

## Guardrails

- 不集成外部工具，所有审查由 AI 完成
- 不做安全漏洞或性能分析
- 行号尽量精确；若无法确定精确行号，给出方法名定位
- 审查完所有文件后再输出报告，不逐文件打断
- 若变更文件超过 20 个，优先审查源码文件（即代码逻辑文件，排除配置文件、文档、构建产物等非代码文件），其余文件简要过一遍
